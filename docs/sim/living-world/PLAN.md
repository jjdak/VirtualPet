# W1 两角色实时小世界：执行计划

2026-11-04，先固定范围再实施。用户授权：实时小世界、改变环境、给单个角色线索、独立记忆和存档。E1–E6 冻结，本阶段不是 E7 参数实验；不实施后续世界分支、情境学习或模型训练。

## 体验与范围

两个抽象标记角色在固定小地图自行移动、取食、回营、休息和近距离交换亲历。饥饿/精力驱动生活，无死亡惩罚。玩家可以暂停、逐步、调整速度；改变两个食物点的好坏或开放状态；只给选定角色推荐一个地点。没有剧本安排发现顺序或成功结局。

地图和两个资源位置是双方已有的公共常识。开放状态仅在近距离观察；食物效果只能取食后得知。导演界面看得到真实环境，决策不得读取隐藏效果、远处开放状态或另一个角色的记忆。线索是有来源、有时效的建议，不能改写个人价值或强制打断当前行动。

## 实现安排

1. **计划与结构**：新增 `living_world/{src,web,tests}`，文档在 `docs/sim/living-world/`；运行存档在忽略的 `.runtime/living-world/`。保留旧 E1–E6、Godot 和 Blender。
2. **实时核心**：Python 标准库服务运行固定步进；复用 E2 Agent 的个人经验更新和同伴消息验证，新增逐格行动、需求、局部供给观察、玩家地点建议。E2 不改动；不直接搬入 E3–E6 的全部机制。
3. **交互界面**：无框架 HTML/CSS/JS，地图、角色行动依据/个人记录、环境控制、定向线索、事件日志。默认暂停方便读图，一次开始后由服务端时钟推进，界面断开不改变决策规则。
4. **保存恢复**：带版本的完整状态，含时钟、种子、任务进度、各自记忆、消息去重和玩家干预；三个手动槽、自动存档、JSON 导入导出。恢复后暂停；原状态校验通过才替换。进程重启可恢复自动档；不将存档放入公开源码目录。
5. **验证与记录**：检查信息隔离、近距离执行、推荐与经验区分、传播、干预效果、长时间运行、存档精确续跑、新进程恢复、坏档拒绝；检查 HTTP 输入和浏览器实际操作。记录实际证据和未验收项。

## 验收门槛

- 不干预也能持续生活，两个角色保持独立位置、需求和经验。
- 改变远处食物效果/供应不会直接改变角色记忆；角色到达后实际经历才更新。
- 单人线索只进入该角色的线索记录，可影响之后的选择，但不是必然服从。
- 经验只在近距离通过消息传播；没有全局共享记忆，也不把收到消息计为亲历。
- 保存再恢复后，在相同后续输入下逐步结果完全一致；错误存档不能破坏正在运行的世界。
- 界面真实执行开始/暂停、改环境、定向建议、存取档；浏览器技术验证与用户主观趣味性分开。

## 边界

简单地图寻路由程序提供，不称为学习走路。选择与需要使用预定义规则，经验值会更新，但不会自创技能、训练权重或产生语言对话。视觉只是抽象生活实验，不承诺原 Blender 画质。新情境学习、世界分支、Godot 对接另立下一阶段，不自动展开。

## W1 收尾补充（2026-11-05，用户明确授权）

1. 用已有 Playwright 独立浏览器＋临时本地服务/存档，复现真实 JSON 下载、文件选择器导入、取消/坏档，以及重复开始暂停/读档/单步；不覆盖用户存档。
2. 对发现的控制问题做最小修复，检查请求超时、在途控制状态、确认流程与下载提示。不得把 HTTP 测试替代浏览器文件操作证据。
3. 核心回归与浏览器复核通过后记录截图、机器回执和明确限制；原 CUA 检查作为历史证据保留。
4. W1 单独分支保存源码、文档、小型验证证据至既有 GitHub 仓库。排除 `.runtime/` 存档、私人美术、缓存和依赖；核对远端提交。不自动合并旧 main 或开始 W2。
