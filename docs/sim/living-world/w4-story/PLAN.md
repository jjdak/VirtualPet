# W4 · 一条线索的后来

2026-11-13，先行计划。目标是回到小世界体验，让玩家能沿真实记录看懂“给线索 → 获得亲历 → 告诉同伴 → 同伴改选”。

1. 在现有 W3 双世界页面上增加可播放、逐步跳转的四段过程。默认以已验证的效果互换案例演示，明确它是示例；保留换人、换地点、其他示例和导入 W2 存档。沿用真实世界行为，不编排角色必然成功。
2. 建立独立观察层，按事件追踪线索、指定地点的亲历报告、报告实际送达、同伴使用该报告的决策。以报告身份和来源关联，不把“首次消息不同”当成这条亲历已经传到。观察层不得改正式存档、角色策略或随机规则，也不得使用跨请求共享的全局补丁。
3. 同伴改选的说明同时给出此侧实际选择、无建议世界同一步的选择、当时实际决策依据。要声称这条报告改变了选择，需验证同一决策副本只去掉该报告时选址翻转，并结合原来关闭后续交流的匹配对照。随机探索、先后相关、记录相同等情况分别说明，不把所有到访都归为线索的功劳。
4. 页面上用四段卡片、当前事件说明与地图标记串联过程。回放到某一步只展示已发生的内容；未来节点可用于跳转，但未发生时不泄露结果。首次流程体验从玩家点击给线索开始；内置场景只负责准备起始状态。保留自由时间轴和播放控制，详细统计移到次要位置。
5. 缺少环节、无差异、建议过期、没有送达、收到但未改选时，都展示真实的停留位置和原因。改变收件人／地点后先标记待应用，避免画面仍是旧结果而文案当作新干预；重新生成成功后才替换结果。
6. 验证真实例子 +56 亲历、+59 送达、+66 改选；覆盖零影响、未完成链条、过期、探索和已有同类消息，核对观察层不改变原轨迹与存档。用隔离浏览器检查节点跳转、播放、错误恢复、导入、窄屏、无未来信息泄露，并检查实际截图。
7. 新文档及证据集中于本目录，复用现有依赖。完成后提交短期分支 PR 指向 main，主观易懂程度留待用户体验反馈；不自动扩大到新角色规则、聊天、训练或美术迁移。
