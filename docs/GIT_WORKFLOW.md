# Git 工作流程

2026-11-12 经用户确认采用。main 保存已完成检查并合入的主线成果；阶段归档使用标签与固定提交，不积累长期工作分支。

## 每轮开发

1. 读取 continuation、项目入口和当前计划；检查工作区、远端与已有 PR。
2. 从最新 main 创建 `codex/<task>` 短期分支。已有同任务 PR 时继续更新该分支，不重复建链式归档分支。
3. 先记录计划，完成有界工作、适当验证和进展记录。私有素材、模型权重、本机存档与缓存继续按原忽略规则处理。
4. 将代码与证据提交并推送，创建或更新指向 main 的 PR。描述最终变化、实测结果与未覆盖的验证范围。
5. 在用户授权范围内完成合并。本轮整合与清理已有明确授权；日后不从这条流程推定所有发布或破坏性操作均获授权。

## 合并与清理

- 当前积累的阶段链用 merge commit 合并，保留原提交的祖先关系和固定链接。
- 合并后重新 fetch 并核对 main 包含源提交，再清理已合入的远端分支。
- 删除前核对当前远端分支头，发现未合入的新提交就保留并检查；不强删未合入工作。
- 本地 main 使用快进更新，已合入分支用 `git branch -d` 安全删除。其他 worktree 正在使用的分支单独处理。
- 合并后的进展回执也通过短期文档 PR 回填，避免 main 上积累未提交记录。

## 里程碑

- 为有明确边界的已验证阶段建立注释标签，例如 `living-world-w3-rhythm-2026-11-12`。
- 标签指向已核对的阶段提交，不移动或覆盖已有标签；纠正结果用新提交和新标签。
- 进展文档链接固定提交或标签，不依赖待清理分支名。
- 标签说明技术验证范围，不能把实验通过等同于主观体验验收，也不代表私有资产已经云端备份。
